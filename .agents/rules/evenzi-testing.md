# Evenzi testing rules (Antigravity)

You test Evenzi static design prototypes in `designs/pages/<page>/`, served via `npm run design` (http://localhost:4000).

## 0 · STOP-check (before you test) — wrong-worktree / not-built guard
This repo has MANY git worktrees; the page you're testing lives in ONE. Before testing:
1. Open the page's `_status.md`. It MUST read `STAGE: TEST`. Note its `SPEC_VERSION`.
2. Open `_spec.md` — its `SPEC_VERSION` MUST match. If they differ, or `STAGE` is not `TEST` (`BUILD` = Cursor isn't done; `DONE`/`REVIEW` = wrong worktree or already past test) → **STOP. Do not test.** Tell the human which stage/version you see and that they likely opened the wrong worktree/folder. You can't switch worktrees yourself.
3. Proceed only when `STAGE: TEST` and the versions match.

## Re-test contract (EVERY run — never reuse a prior pass)
- **Re-read `_test.md` FRESH every run.** The matrix changes between versions (rows get added/renamed). Test the matrix that's there NOW — never replay an earlier run's row list from memory.
- **Write a NEW, dated `## <date> — Antigravity — against SPEC_VERSION <v>` entry** (append; never edit/"update" a previous entry). `<v>` MUST equal the current `_spec.md` SPEC_VERSION.
- **Cover EVERY matrix row** — your result-row count must equal `_test.md`'s row count. Skipping one = record it as `SKIP` + reason; never silently omit (silent omission reads as "covered" when it wasn't).
- **Evidence, not inference.** Each note states what you ACTUALLY exercised in the running page and what you observed (e.g. "clicked tab → panel B shown, aria-selected flipped"). A class/listener "present in the code" is NOT a PASS — interaction/visual/responsive rows must be driven in the browser. "Looks present in code" is a test failure, not a feature pass.
- **Don't trust prior PASSes.** After a fix loop, re-test the WHOLE matrix against the current build — a previous PASS may be stale, and a previously-shallow PASS may have hidden a defect.

## Source of truth — read these first
- `ai/agents/test_engineer.md` — Evenzi test role book (the sad-path catalogue, `prefers-reduced-motion`, dark-mode contrast, real-device + TalkBack reality, content-length stressors).
- The page's `_test.md` — the test source of truth for THIS page (generated by `/spec-kit`). Run every matrix row; it is authoritative.

## How to test a kit page
1. Read `_test.md` in the page folder. **Run section 1 (Smoke) first** — if any smoke row fails (page broken / unstyled / missing `data-page` / missing chrome), stop and flag for rebuild; deeper rows would false-pass.
2. Work sections 2–6 in order. Record each row `PASS` / `FAIL` / `SKIP` in `_findings.md` by row ID, under a dated `## <date> — Antigravity — against SPEC_VERSION <v>` heading, using the table schema already in `_findings.md`.
3. Manual rows (section 7 — mobile real-device, WhatsApp in-app browser, TalkBack) are tagged "agent: skip and flag for human" — record `SKIP (human)` so they stay visible.
4. When done, bump `_status.md` → `STAGE: REVIEW`, `NEXT: /spec-kit-review <page>`.

## Test floor (always — even for a page with no kit)
- Console clean on load and after each interaction.
- 6 widths: 360 / 390 / 414 / 768 / 1024 / 1440 — no horizontal scroll, no clipping, touch targets ≥44px on mobile.
- a11y: visible focus ring on keyboard nav, alt text on images, programmatic labels (not placeholder-only), logical heading order, status never color-only.
- `prefers-reduced-motion: reduce` honored; dark-mode contrast WCAG AA (4.5:1 body, 3:1 large).
- Edge/sad paths: empty, loading, error-with-recovery, long content (90+ char names, Devanagari ~1.4× width), single vs many items.
- **Runtime-dependency resilience** — the page must NOT depend on a runtime third-party CDN for layout-critical CSS/JS. **Actively simulate the failure:** after first load, block the network (or third-party requests in devtools) and hard-reload — the layout MUST hold (no collapse to unstyled vertical flow). ⚠️ A successfully-loaded CDN returns HTTP 200 and throws no console error, so the console-clean check and the link-audit will NOT catch this — you must trigger the failure yourself. If the page collapses, that is a FAIL: the asset must be vendored locally, not CDN-loaded.
