Ops · prod-risk PR-1
Fixed live — push webhook was silently 401-ing every dispatch Root cause: the database trigger was sending the raw shared secret as the signature header while the route required an HMAC of the request body, so every single push dispatch was rejected with a 401 and no browser push had ever actually been delivered. Replaced with public.dispatch_notification_push(), which HMAC-signs the body. Verified end to end on the live database: net._http_response returned 200 {"ok":true} with a matching push_dispatch_log row. The route also now accepts the shared-secret header for compatibility (that part is code on the audit branch). Outstanding: one founder-side confirmation that the OS toast actually appears on a subscribed device.

This is no longer treated as a launch blocker: the founder's locked call (Q5) is to hide the Upgrade CTA entirely until a gateway is planned.
